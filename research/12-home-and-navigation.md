# Главная страница, портфель проектов и страница проекта

Дата: 15 ноября 2026 года. Поручение пользователя 15.11.2026 после разбора пакета D-Tools: «По этому исследованию можно основй дашборд и интерфейс переосмыслить». Все предложения ниже — **H**. MVP-SPEC не менялся, код не менялся.

**Основания.** Пакет D-Tools — [research/04 §18](04-sources.md#18-пакет-d-tools-как-референс-для-av-платформы-15-ноября-2026), §5 пакета (информационная архитектура); выводы по ролям — [research/09](09-role-workplaces.md); правила обзора — MVP-SPEC §14 (OVW-01–OVW-04) и §11.1 (PLAN-05, PLAN-06); оболочка — ADR-004 (Desk).

## 1. Что есть сейчас

Просмотрено 15.11.2026 в прототипе под учебным руководителем, ширина 1440 px, и по коду.

| Место | Сейчас | Что мешает |
|---|---|---|
| Панель модулей (Dock) | «Обзор», «Продажи», «Проекты» | Разделы названы по модулям, а не по работе человека; каждая роль видит свой набор только через стартовую страницу |
| Меню разделов (Sidebar) | Наши страницы и сырые DocType: `Project`, `Quotation`, `AV Handover`, `Task`, `Customer` | Английские системные названия; ссылки ведут в штатные списки ERPNext, где нет наших правил отображения |
| «Обзор» (`av-overview`, DIR-01) | Только AV Director. Воронка из пяти плиток, «Требуют внимания», затем по большой карточке на каждый проект | При 157 открытых проектах — длинная лента карточек; нет фильтров по PM и клиенту; нет «Мои / Все»; PM и Sales этой страницы не видят |
| Проект | Штатная форма ERPNext `Project` | Нет своей страницы проекта: доска работ, передача, база предложения и препятствия разнесены по разным экранам |

В учебной базе 156 из 157 открытых проектов — «Неизвестно»: это остатки тестов (вопрос об очистке уже записан в NEXT_SESSION). Интерфейс всё равно должен выдерживать сотни строк.

## 3. Предложение (H)

### 3.1. Навигация

- Панель модулей: «Главная», «Продажи», «Проекты». Новые иконки («Закупки», «Склад», «Поле») — только вместе с модулем и только ролям с правом.
- Меню разделов — русские названия по задаче: «Мои предложения», «Передачи», «Клиенты»; «Доска работ», «Мои задачи», «Все проекты». Штатные списки ERPNext — в свёрнутой группе «Справочники» для тех, кому они нужны.

### 3.2. «Главная» вместо «Обзора»

Одна страница для всех ролей; блоки показываются по праву, деньги — отдельным правом на блок (research/09 §2, CTL-01). Переключатель «Мои / Все»; «Все» — по праву (как в D-Tools Cloud, RW9).

| Блок | Кто видит | Источник данных |
|---|---|---|
| Мои дела: просрочено / сегодня / неделя, передачи и предложения, ждущие моего действия | Все | `pm_api.get_my_tasks`, стадии `sales_api` |
| Воронка: выданы, ждут PM, возвращены, истекают за 30 дней | Sales (свои), руководитель | `overview._funnel` |
| Проекты в работе — плотная таблица | PM (свои), руководитель (все) | `overview._projects` |
| Позже: что заказать, изменения на согласовании, платежи | По модулю и праву | После складского, CR и финансового срезов |

Стартовая страница после входа становится «Главной» для всех, кроме монтажника: для него экран «Сегодня» (research/09 §6).

### 3.3. Таблица проектов

Строка проекта (OVW-01, OVW-03): статус · проект и клиент · PM · главное препятствие с владельцем и сроком · ближайшая веха · индикаторы направлений · плановое окончание · принятая сумма (по праву). Фильтры: статус, PM, клиент, «только мои»; сохранённые представления. Клик по строке — страница проекта. На ширине до 768 px строка превращается в карточку.

Индикатор направления — маленький квадрат с цветом статуса и подписью в единицах направления («работы 3/10»). Серый — нет данных, а не ноль.

### 3.4. Страница проекта

Новая Desk-страница `av-project/<проект>`; прямые ссылки на вкладки.

- **Шапка:** название, клиент, PM, статус с причинами (OVW-03), база — версия предложения и принятая сумма (по праву), окончание.
- **Пять индикаторов:** работы, закупка, монтаж, проверки, деньги. Нет плана проверок — «нет плана», не 100 %.
- **Вкладки сейчас:** «Обзор» (все препятствия, ближайшие вехи, позже журнал) и «Работы» (существующая доска, отфильтрованная по проекту). «Состав», «Закупка», «Изменения», «Проверки», «Документы» появляются вместе со своими модулями.
- **Права:** те же серверные проверки, что у доски и обзора; страница чужого проекта — понятная граница без раскрытия названия (OVW-04).

## 5. Что не проверено

- Макеты показаны в чате, в прототипе не собирались; удобство не проверялось на людях.
- Поддерживает ли Desk v16 вложенные адреса страниц (`av-project/<проект>/works`) без правки core — не проверено; запасной вариант — параметр в адресе.
- Проекты без передачи (созданные вручную в ERPNext) показываются с «База: нет данных». По решению пользователя 15.11.2026 проект появляется только из передачи Sales → PM (research/04 §18), ручное создание закрыто на сервере (PRJ-01).

## 6. Композиция всего продукта по образцу D-Tools Cloud

Слова пользователя 15.11.2026: «В целом всю ux/ui и дизайн композиции продукта по примеру D Tools можно сделать», затем «Можешь и в интернете поискать рефернсы картинки интерфейса». Устройство D-Tools Cloud восстановлено по справочному центру и его скриншотам (DT5–DT11 в [research/04 §18](04-sources.md#18-пакет-d-tools-как-референс-для-av-платформы-15-ноября-2026)). ### 6.2а. Два шаблона экранов

Почти все экраны D-Tools собраны из двух шаблонов. Это главный вывод для нашей композиции (H).

- **Реестр** (проекты, сделки, заказы, изменения): заголовок, переключатель «список / Kanban», выгрузка, поиск; ниже «Все / Мои / Доступные мне», фильтры-«пилюли» и «Все фильтры», справа одна главная кнопка «Создать …»; при необходимости — полоса счётчиков по статусам над таблицей.
- **Карточка записи** (проект, предложение, заказ): шапка «назад, название и номер, статус с выбором, ключевые люди, сумма, действия»; слева панель разделов (у нас — широкая, во всю высоту, без рамки вокруг записи: иконка, название, число; слова пользователя 15.11.2026: «C и не узкая»); рядом дерево группировок с суммами; в центре таблица или плитки; справа задачи, заметки, файлы, журнал.

Предложение: сделать эти два шаблона общими Vue-компонентами в `apps/av_platform/frontend` и собирать из них все будущие экраны. Тогда новые разделы будут выглядеть единообразно без отдельной вёрстки каждого.

### 6.2б. Черты стиля

Слова пользователя 15.11.2026 после просмотра скриншотов: «Мне прям очень нравится дизайн и логика расположения элементов». Логику расположения переносим целиком (§6.2а). Стиль — по общим чертам, своими токенами внутри контейнера `.av-desk` (ADR-004). Оболочка Desk — панель модулей и меню — остаётся видом Frappe.

| Черта D-Tools | Наша реализация (H) |
|---|---|
| Белые поверхности, тонкие рамки, много воздуха между блоками; плотные таблицы со светлой строкой заголовков | Так же, на компонентах frappe-ui |
| Статус — сплошная цветная «пилюля» со стрелкой, меняется прямо в строке | Пилюля статуса с выбором; цвета — настройка статусов (ARC-02); текст на пилюле всегда, цвет не единственный признак |
| Один акцентный цвет для главных действий и ссылок | Один свой акцент, не зелёный D-Tools; одна главная кнопка на экран |
| Фильтры-пилюли «Стадии: все», сегментные переключатели «Все / Мои» | Так же |
| Крупная цифра для ключевой суммы, мелкая расшифровка под ней | Так же, только по праву на деньги |
| Люди — аватары с «+» для назначения | Так же; назначение — через серверную проверку |
| Панель разделов — иконки с подписью снизу | Так же; иконки — свой набор (Lucide, уже в Desk) |

Не берём: шрифт, логотип, точную палитру, иллюстрации и сочетание всего этого в узнаваемый вид D-Tools.

### 6.4. Что меняется в порядке внедрения

Шаги UI-03a–UI-03d из §4 остаются и строятся по этой карте. UI-03a — меню только из того, что уже есть: «Главная», «Продажи», «Проекты». Kanban проектов по стадиям требует поля «стадия проекта»: у ERPNext Project есть только статус Open / Completed / Cancelled. Состав стадий и их группы решает пользователь; это отдельный шаг после UI-03b.
