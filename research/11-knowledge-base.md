## 3. Предлагаемое устройство (H)

**Статья — одна тема.** Заголовок, короткое определение или ответ, подробности, ссылки «Подробнее и доказательства» на разделы research и внешние источники. Если статья опирается на предположение, это видно (метка H, как в спецификациях).

**Один владелец факта.** Доказательства, статусы и решения остаются в research, MVP-SPEC и ADR; статья — читаемая сводка. Новый факт сначала попадает к владельцу, затем статья обновляется. Иначе появятся два расходящихся источника (AGENTS.md, правило 4).

## 4. Инструмент: Frappe Wiki v3

Проверено по документации (K1–K4), в прототипе не запускалось.

| Свойство | Значение для нас |
|---|---|
| MIT, v3.5.0 от 12.11.2026, ветка `version-3` — stable для Frappe v15 и v16 | Можно ставить рядом с `av_platform` на той же платформе; с Frappe 16.55.1 не проверено |
| Разделы (spaces) с правами чтения и записи по ролям | Закрытая база только для команды |
| Редактор Tiptap, страницы хранятся как Markdown, история каждой страницы | Статьи можно переносить и выгружать |
| Запросы на изменение: правка → просмотр разницы → одобрение | Контроль качества статей, в том числе предложенных ИИ |
| Поиск (SQLite FTS5), оглавление, светлая и тёмная тема, PDF | Удобное чтение |
| Markdown-копия каждой страницы и `llms.txt` | Источник для ассистента ADR-005 |
| GitHub Sync: раздел из папки Markdown в репозитории GitHub, только в одну сторону; закрытый репозиторий — через GitHub App только на чтение | Подходит, если исходники в закрытом GitHub; страницы синхронизированного раздела правятся в GitHub, а не в вики |
| Webhook GitHub требует публичного адреса сайта | Без него — кнопка «Sync now» |
| `bench wiki preview-docs <папка> --route <route> --watch` | Предпросмотр локальной папки; только в developer mode — не для рабочего сервера |

## 5. Где хранить — варианты для решения пользователя

| Вариант | Как работает | Плюсы | Минусы |
|---|---|---|---|
| А. Вики на сервере компании, статьи пишутся прямо в редакторе | Frappe Wiki на сервере DEP-01, закрытый раздел | Всё внутри компании; запросы на изменение и история встроены | Статьи не в Git; резервная копия — вместе с базой Frappe |
| Б. Закрытый репозиторий GitHub + GitHub Sync в вики компании | Markdown в закрытом репозитории, вики забирает изменения | Git-история, правка агентами по запросам на слияние | Исходники у GitHub, не на сервере компании |
| В. Git на сервере компании + свой импорт | Markdown на своём Git-сервере, импорт своим скриптом | Всё внутри компании и в Git | Нужен свой импорт: GitHub Sync работает только с GitHub, `preview-docs` — только в developer mode |
| Г. Папка в этом публичном репозитории | `knowledge/` рядом с research | Сразу, без сервера | Всё видно всем; не подходит для закрытых материалов |

Предложение H: черновики, собранные только из research (он уже публичен), можно начинать до решения; закрытые материалы — только после выбора варианта А, Б или В. Предпочтение — А вместе с DEP-01, если не нужна правка через Git.

## 6. Использование ИИ (H, по ADR-005)

- Агенты разработки (Claude Code, Codex) составляют черновики статей из research; человек проверяет и одобряет.
- В вики черновик ИИ проходит запрос на изменение — тот же принцип «ИИ предлагает, человек подтверждает».
- Ассистент продукта может отвечать по базе знаний через `llms.txt` и Markdown-копии страниц; закрытые статьи — только локальной моделью.
- Содержимое статей для ИИ — данные, не инструкции.
