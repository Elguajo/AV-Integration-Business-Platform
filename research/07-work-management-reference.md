**Наблюдение по скриншотам пользователя (14.11.2026):**
- ClickUp: у Space есть вкладки видов (Overview, Board, List, Calendar, Mind Map, пользовательский вид), внутри — папки по этапам производства. В левом меню отдельные пункты Inbox, Replies, Assigned Comments, My Tasks, Planner, Whiteboards.
- YouGile: доски проекта показаны вкладками. Переключатель «Доска / Гант / Календарь» стоит рядом с панелью фильтров по стикерам (исполнитель, дедлайн, приоритет).
- Карточка YouGile показывает: отметку выполнения, ID задачи с префиксом проекта, счётчик сообщений чата, время в работе, прогресс чек-листа (например, 1/6). У колонки есть счётчик задач. В колонке DONE часть карточек отмечена выполненной, часть — нет. Это подтверждает, что колонка и признак «выполнена» в YouGile независимы.

## 3. Механизмы, которые стоит учесть

**3.1. Права на действие зависят от роли и назначения.** В YouGile «Сотрудник» может выполнить только свои задачи или задачи без исполнителя, а «Управляющий» — любые ([роли](https://help.yougile.com/books/baza-znanii-yougile/page/roli-polzovatelei-v-proektax)). Роль проекта настраивается детально: `move` = no / board / project / yes, `assignUsers` = no / yes / add-self / set-self / change-from-self ([TaskPermissionsDto](https://ru.yougile.com/api-v2#/schemas/TaskPermissionsDto)). Для монтажников и программистов это прямо применимо. **H:** право перемещать или завершать чужую работу — отдельное серверное правило; «взять себе» — отдельное действие, а не полное право назначать.

**3.2. Маршрут переходов и обязательные данные.** YouGile даёт расширениями:
- «Workflow» — из каких колонок в какие разрешено перемещать и где разрешено создавать задачи ([workflow](https://help.yougile.com/books/baza-znanii-yougile/page/workflow-nastroika-rabocego-processa));
- «Формы» — обязательные поля при переносе в колонку или при выполнении ([формы](https://help.yougile.com/books/baza-znanii-yougile/page/formy-vvod-dannyx-pri-soversenii-deistvii-s-zadacei));
- «Согласование» — переход дальше только после одобрения всех согласующих, при отказе указывается причина ([согласование](https://help.yougile.com/books/baza-znanii-yougile/page/rassirenie-soglasovanie-zadaci-v-kolonke)).

У нас этапы уже являются настройками (ARC-02), а отказ сервера уже показывается с причиной. **H:** добавить к `AV Work Stage` допустимые переходы и требование при входе в этап (например, комментарий или вложение для «На проверке»). Проверка остаётся на сервере, без отдельного движка автоматизаций. Завершение по-прежнему не доказывает PASS или приёмку (PLAN-03).

**3.3. Мягкий WIP-лимит.** В YouGile лимит задач в колонке не запрещает перенос, а только показывает превышение ([лимит](https://help.yougile.com/books/baza-znanii-yougile/page/limit-zadac-v-kolonke)). В справке по настройке Board view ClickUp WIP-лимит не упомянут. **H:** необязательный лимит этапа с предупреждением; низкий приоритет.

**3.4. Зависимости и перенос сроков.**
- ClickUp: при включённом Reschedule Dependencies сдвиг даты блокирующей задачи сдвигает зависимые на то же число дней, с пропуском нерабочих дней. Закрытие задачи с открытыми зависимостями даёт только предупреждение, и только при включённом Dependency Warning ([rescheduling](https://help.clickup.com/hc/en-us/articles/6304547785367-Rescheduling-dependencies)).
- YouGile: автопланирование включено по умолчанию на всех досках, отключить его может только Управляющий ([Гант](https://help.yougile.com/books/baza-znanii-yougile/page/diagramma-ganta)).

PLAN-04 исключает автоматический перенос цепочки из минимума и требует показывать затронутые работы. Наша жёсткая проверка завершения строже, чем у обоих продуктов, и это сознательное преимущество. **H для PM-03:** при изменении даты показывать список затронутых работ и вех с предлагаемым сдвигом; применять только подтверждением PM и только к рабочему плану, не к договорным датам.

**3.5. Базовый план и критический путь.** ClickUp делает снимки дат (baselines; на платных тарифах Business и выше) и показывает критический путь и запас времени ([baselines](https://help.clickup.com/hc/en-us/articles/34358881283863-Use-baselines-on-Gantt-view), [critical path](https://help.clickup.com/hc/en-us/articles/6310440099479-Critical-Path-and-Slack-Time)). Для AV это прямо соответствует PLAN-01: плановые даты отличаются от фактических, а договорные обязательства не переписываются. **H для PM-03:** зафиксированный базовый план (снимок дат при передаче проекта или при утверждении CR) и отображение отклонения. Критический путь — после первой версии timeline.

**3.6. «Мои задачи».**
- ClickUp делит работу на Today, Overdue, Next и Unscheduled; задача без дат иначе пропадает из вида ([My Work](https://help.clickup.com/hc/en-us/articles/18947060934423-Use-the-My-Work-card-in-Home)).
- YouGile даёт вкладки «Мои задачи», «Порученные мной» и «Избранные», личные списки и приватные задачи, невидимые даже администратору ([Мои задачи](https://help.yougile.com/books/baza-znanii-yougile/page/razdel-moi-zadaci)).

**H для PM-02:**
- группы «Просрочено / Сегодня / На этой неделе / Позже / Без срока»;
- вкладка «Поручено мной» по автору назначения ToDo;
- действия прямо из списка: смена этапа тем же серверным методом, что на доске, и открытие карточки.

Приватные задачи не переносим: они вне правила «один владелец факта» и вне границы V1.

**3.7. Настройки доски.** ClickUp позволяет:
- выбирать поля на карточке;
- сворачивать пустые колонки;
- показывать закрытые задачи;
- включать «Me Mode»;
- группировать строками (subgroups, по сути swimlanes);
- сохранять вид как личный или общий ([Customize Board view](https://help.clickup.com/hc/en-us/articles/35342044832279-Customize-Board-view), [subgroups](https://help.clickup.com/hc/en-us/articles/8352728309271-Use-subgroups-in-Board-view)).

**H для PM-01, в порядке ценности:**
1. Строки по помещению или системе. Это AV-специфичная группировка, которой нет у обоих продуктов в готовом виде.
2. Свёрнутая колонка «Завершено» с последними N работами.
3. Фильтры, сохранённые в адресе страницы, чтобы видом можно было поделиться ссылкой.
4. Счётчики колонок.

Сохранённые общие виды — позже.

**3.8. Время в этапах.** Отчёт YouGile «Время в колонках» показывает среднее время задач в каждой колонке и узкие места ([отчёт](https://help.yougile.com/books/baza-znanii-yougile/page/otcety-vremia-v-kolonkax)). **H:** для этого нужна история смены `av_stage`. Ведёт ли ERPNext историю версий Task (track changes), не проверено. Если нет, нужен отдельный журнал переходов, и это следует решить до отчётов, иначе данные за прошедший период будут потеряны.

**3.9. Whiteboard.** ClickUp:
- редактирование в реальном времени с курсорами;
- превращение фигуры, стикера или текста в задачу с выбором списка и заполнением обязательных полей;
- живые карточки задач на холсте;
- доступ по ссылке без аккаунта ([Whiteboards](https://help.clickup.com/hc/en-us/articles/6326615000471-Intro-to-Whiteboards), [convert](https://help.clickup.com/hc/en-us/articles/6326217118615-Add-items-to-a-Whiteboard)).

**H для PM-04 (Excalidraw, MIT, по MVP-SPEC §2.3):**
- доска привязана к проекту;
- сцена хранится в DocType с проверкой параллельного изменения, как на Kanban;
- «Создать работу из стикера» вызывает серверный метод, который проверяет права и создаёт обычную задачу ERPNext;
- на холсте хранится ссылка на задачу, а актуальные название и этап подгружаются с сервера.

Совместное редактирование в реальном времени у Excalidraw требует отдельного сервера; в первой версии его не делаем, это ещё нужно проверить. Публичный доступ без аккаунта противоречит правилу 3 и в V1 не входит.

**3.10. Чат в задаче и ИИ.** В YouGile у каждой задачи свой чат: на скриншоте это счётчик на карточке. У YouGile есть страница «Подключение MCP ChatGPT/Claude», у ClickUp — собственный MCP-сервер (раздел MCP в [документации API](https://developer.clickup.com/docs/tasks)). Чат не входит в V1 (ROADMAP 14.11.2026); у Frappe есть комментарии к задаче. Наличие MCP у обоих подтверждает приоритет нашего MCP, но его правила остаются прежними: отдельная учётная запись и запись только с подтверждением человека.

## 4. Чем отличаемся

- Место работы (помещение, система) — основная ось группировки и фильтров, а не произвольное поле.
- Одна задача ERPNext во всех видах; никаких зеркал и копий с разными правами.
- Завершение проверяется сервером: блокировка и зависимости — отказ, а не предупреждение. Завершение не означает PASS или приёмку.
- Рабочий план отделён от договорных сроков; базовый план и CR связаны.
- Права одинаковы в доске, API, поиске и экспорте. Известный остаточный риск — Desk Task/Project в ERPNext (prototype/README.md, PM-01).

## 5. Ручной просмотр в аккаунтах, 14 ноября 2026

Просмотр шёл во встроенном браузере приложения; в свои аккаунты пользователь вошёл сам. Действия только на чтение: открывались виды, меню, карточка и диалоги. Диалоги закрыты кнопкой «Отмена», вид YouGile возвращён на «Доска». В пространствах реальные данные, поэтому ниже описано только устройство интерфейса.

**ClickUp**
- **Доска.**
  - Над колонками строка состояния вида: «Grouping by: Status», «Subtasks: Collapsed», «Sorting by None».
  - Подсказка «Adjust your status filter to show closed tasks»: закрытые задачи скрыты фильтром, а не удалены.
  - У колонок есть счётчики и «Add group».
  - Карточка показывает обложку, название, значки описания и вложений, исполнителей, диапазон дат (просроченный — красным) и приоритет.
- **Настройки вида** совпадают со справкой (W3). Группировка по Status, Assignee, Priority, Tags, Due date, Task Type; строки добавляются через «Add subgroup».
- **Задача** открывается на своём адресе (`/t/<workspace>/<id>`).
  - Сверху путь расположения и действия «Add to another List», «Move task».
  - **Поле статуса** — кнопка из трёх частей: текущий статус, стрелка «следующий статус» и галочка «завершить». Перевод на следующий этап делается одним нажатием, без списка.
  - Список статусов разбит на группы Not started / Active / Done / Closed. В этом пространстве «IN REVIEW» отнесён к Done: группа задаётся настройкой, а не названием.
  - Связи: «Relate a Task or Doc», «This task blocks…», «This task is blocked by…», «New custom relationship».
  - Поля делятся на «Fields from <тип задачи> type» и «Fields from this List»: их набор зависит и от типа задачи, и от места.
  - Есть «Collapse empty fields», отдельные комментарии и активность.
- **My Tasks** собрана из карточек: Recents, Agenda, My Work, Assigned to me, Assigned comments, Priorities, AI StandUp. В My Work вкладки To Do / Done / Delegated и группы Today / Overdue / Next / Unscheduled со счётчиками и добавлением прямо в группу.
- **Planner** без подключённого внешнего календаря только предлагает подключить Google или Outlook.
- **Whiteboard.**
  - Привязан к месту в иерархии: Space → Folder → List.
  - Инструменты: ClickUp items, Draw, Shapes, Arrow, Sticky Note, Text, Frame, Image, Templates, AI tools.
  - Холст в дереве доступности называется `application "tldraw"`.
  - Лицензия tldraw — source-available: в производственной среде её нельзя использовать без коммерческой или пробной лицензии с ключом ([LICENSE.md](https://github.com/tldraw/tldraw/blob/main/LICENSE.md), `gh api` 14.11.2026). Excalidraw — MIT.
  - **Вывод:** выбор Excalidraw в MVP-SPEC §2.3 подтверждён. tldraw возможен только по решению пользователя о покупке лицензии (ADR-003).
- **Gantt-вид** в пространстве не создан; создавать вид в рабочем аккаунте я не стал.

**YouGile**
- **Доска.** Над колонками переключатель «Доска / Гант / Календарь» и фильтры по стикерам. У колонок счётчики и «Добавить задачу», справа «Создать колонку / сводку / зеркало».
- **Задача** открывается боковой панелью, её адрес содержит ID (`#TRE-…`).
  - Вкладки: **Чат** (открывается первым), «Инфо / Лог», «Описание», «Подзадачи». Работа строится вокруг переписки.
  - Системные события, например «Дедлайн по задаче был просрочен» и «…назначены исполнителями», приходят в чат задачи.
- **«Инфо / Лог»:**
  - автор и дата создания;
  - отдельные поля «Исполнители», «Ответственный», «Поручили»;
  - расположение «проект » доска » колонка» и действия «Показать на доске», «Переместить»;
  - стикеры;
  - **«Кто видит задачу»** — каждый человек с причиной доступа («Администратор», «Добавлен в проект, где находится задача»);
  - «Ссылки на другие задачи»;
  - «Лог событий по задаче» с фильтрами по дате и типу действия.
- **Гант** сгруппирован по колонкам доски, подзадачи разворачиваются. Колонки: исполнитель, диапазон дат и число **рабочих дней**. Масштаб «Недели», кнопка «Сегодня», переключатель «Автопланирование» (включён).
- **«Мои задачи»** — вкладки «Мои задачи», «Порученные мной», «Избранные», «Чужие задачи».
  - Во вкладке «Мои задачи» есть списки, приватные списки и «Входящие» с фильтром и сортировкой.
  - «Чужие задачи» группируют задачи коллег по исполнителю со счётчиками — это обзор загрузки для руководителя.
- **Участники и роли проекта.**
  - Участника можно добавить лично или через отдел.
  - Кроме трёх встроенных ролей есть пользовательские; роли копируются из другого проекта.
  - В редакторе роли права задаются по дереву объектов проект → доски → колонки. Наследование видно по пометкам «Как у проекта» и «Изменено».
  - Группы прав: Проект, Доски, Колонки (включая «Добавление задачи»), Все задачи. В «Все задачи» — десятки отдельных действий: просмотр, выполнение, назначение, перемещение, архивирование, связывание, удаление, сообщения и файлы.
  - Отдельно переопределяются права для трёх отношений: **«Задачи, созданные пользователем»**, **«Назначенные на пользователя задачи»** и **«Задачи, где пользователь добавлен в уведомления»**.

**Что это добавляет к предложениям H**
- **Права по отношению к задаче.** Автор, исполнитель и наблюдатель получают права поверх роли. Так в YouGile сделано «монтажник видит и меняет только своё». У нас это кандидат на правила Frappe `has_permission` и `permission_query_conditions` по назначению. Решение связано с открытым вопросом о правах Desk (prototype/README.md, PM-01).
- **«Кто видит и почему».** Объяснение доступа прямо в карточке — сильный ответ на правило 3 и PLAN-06. **H:** серверный метод «кто видит эту работу и по какому основанию» для PM и администратора.
- **Перевод на следующий этап одной кнопкой.** На телефоне это удобнее перетаскивания и соответствует PLAN-03 (перемещение без перетаскивания). **H для PM-01:** кнопка «Следующий этап» на карточке.
- **Исполнитель и ответственный — разные поля в YouGile.** В ERPNext у Task есть назначения (ToDo) и `completed_by`, но нет «ответственного». Нужно ли различать эти роли, покажет процесс компании (F-проверка), а не интерфейс.
- **Рабочие дни в Ганте — основа PM-03.** Нужен календарь рабочих дней (Holiday List в ERPNext), иначе длительность монтажа считается неверно.
